# Ручная проверка записи до судьи

Предложение не применено к рабочей базе. Для отдельной ручной проверки нужны
две подготовленные схемы: сначала `20261109_prejudge_artifacts.sql`, затем
`20261109_prejudge_manual_jobs.sql`. Они создают только три новые таблицы;
очередь `lost_processing_jobs`, её индексы и существующие таблицы не меняются.
Нельзя одновременно применять старый черновик частичной очереди
`20261109_manual_staging_queue.sql`. При последующем включении очереди можно
отдельно применить её исходную миграцию после проверки текущего состояния схемы.

`runManualPrejudge` создаёт идентификатор `manual-test:<uuid>` только в отдельной
таблице ручных запусков; автоматическая очередь не видит этот идентификатор и
не может занять задание после аварии. До судьи в общую таблицу материалов
сохраняются исходная переписка, готовые транскрипты и пакет фактов с признаком
`run_kind=manual`. Рабочие задания игнорируют такие строки при проверке ранее
обработанного перехода. Фактический переход и дата дополнительно проверяются
обычным чтением истории Битрикса внутри `processDeal`. Режим принудительно
тихий: вызова доставки, комментария или уведомления в этом runner нет.

Ручной путь пока **не подключает журнал `sttAttemptPolicy`** и не возобновляет
ранее полученные фрагменты незавершённого звонка. Повторное использование
завершённых транскриптов по SHA реализовано в отдельном штатном opt-in пути,
но не должно ошибочно считаться проверенным для этого ручного runner. Вердикт
и итог писателя сохраняются в `judge_result` той же staging-таблицы в одной
транзакции с завершением ручного прогона. Сырая копия `analysis.communications`
не дублируется: безопасная проекция коммуникаций уже сохранена отдельно. Основная
таблица анализов не меняется. Если
процесс упал, статус его изолированной записи может остаться `running`; он не
попадёт в автоматическую очередь и виден для последующей ручной сверки.

Для применения нужен серверный DB-пользователь с правом создания таблиц и
доступом при включённом RLS. Не открывать таблицы `anon`/`authenticated`;
проверить default grants, владельца и фактическую роль приложения. Сначала
проверить имена и права на чистой базе и синтетическую запись с `ROLLBACK`;
в рабочем проекте создавать схему только после ревью и проверки отсутствия
одноимённых объектов. Тексты/файлы записей в Git не сохранять.

`20261109_prejudge_manual_smoke.sql` проверяет все три таблицы синтетическими
строками и откатывает транзакцию. Выполнять целиком на одном выделенном
подключении, не через инструмент с неизвестным управлением транзакциями;
при ошибке явно выполнить `ROLLBACK` до возврата подключения в пул.

Локальные тесты: `node --test tests/restore-pipeline/manual-prejudge.test.mjs`
и `OTKAZY_LOCAL_PG_SUITE=manual-prejudge bash tests/restore-worker/run-local-real-pg.sh`
в заранее подготовленной Linux-среде с PostgreSQL и Node 24. Второй тест
использует отдельную временную базу, Unix-сокет и моковые Bitrix/модели.
