# Правила отладки n8n воркфлоу

## Запуск воркфлоу
- Запускать ТОЛЬКО через `n8n_test_workflow` MCP (workflowId, webhookPath, triggerType='webhook', data, waitForResponse=false)
- НИКОГДА curl или bash — песочница блокирует bezalv.ru (403)
- После запуска — СТОП. Ждать подтверждения Сани "закончилось"
- НЕ проверять статус execution самостоятельно

## Редактирование воркфлоу через MCP

**Правка сразу работает в проде.** Публикации нет, ждать её не надо, «ждёт публикации» в отчётах не писать.

Порядок обязателен:
1. ПЕРЕД правкой — `n8n_get_workflow` (mode `filtered` для конкретных нод), чтобы видеть текущее состояние
2. ПЕРЕД правкой — бэкап затрагиваемых нод в `tmp/backup/` выгрузкой: `node bench/dump-node.mjs --wf <id> --node "<имя>"`. Руками код не переносить — на 12–20 КБ это гарантированная опечатка
3. ПЕРЕД правкой — прогон логики на моках из `tests/`
4. Правка через `n8n_update_partial_workflow`, точечно, по одной ноде за вызов
5. ПОСЛЕ правки — `n8n_validate_workflow` по каждому затронутому воркфлоу
6. ПОСЛЕ правки — проверить, что изменения на месте: идемпотентные замены маркеров на себя (`patchNodeField` падает, если `find` не найден)

- `n8n_update_full_workflow` — только когда нужен весь воркфлоу целиком
- Точка отката: локальные снапшоты пишутся ПЕРЕД изменением, поэтому нужна версия, созданная непосредственно перед правкой. Проверять диффом (`mode: "diff"`), а не по времени
- Скрипт выгрузки работает через `N8N_API_KEY` из `.env`; ключ MCP-сервера скриптам недоступен — это разные каналы доступа
- Если код вставлялся в ноду руками через MCP-вызов, после правки выгрузить ноду и сверить с файлом-источником побайтово

## Типичные ошибки
1. **Молчаливый 404 на webhook** — webhookId не совпадает с path. Проверить оба значения
2. **$env не работает в Code-ноде** — перенести в expression-поле HTTP Request ноды
3. **SplitInBatches не собирает результаты** — использовать ТОЛЬКО $input.all() в collect-ноде
4. **n8n_autofix_workflow** — НЕ ИСПОЛЬЗОВАТЬ, ломает typeVersions
5. **Пустая транскрипция** — проверить двухпроходную логику (stereo → mono fallback)

## Диагностика
- Логи execution смотреть через n8n UI (делает Саня)
- Для отладки SQL — проверить через Supabase MCP execute_sql
- При ошибке воркфлоу — сначала проверить что credential правильный (Otkaz:*, не Priostanovlenie:*)

## Webhook paths этого проекта

- `lost-batch` — пакетный прогон
- `lost-transcription` — транскрипция звонка
