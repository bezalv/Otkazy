# Стенд судьи и писателя

Гоняет любую модель на сохранённом входе и сравнивает с эталоном. В базу не пишет,
Битрикс не трогает, уведомления не шлёт.

## Устройство

Вход — `facts_packet` из `lost_deal_analyses.ai_facts_json`, то есть ровно то, что видел Opus.
Запрос судьи собирается так же, как его собирает нода `agent-facts-assembler`: системный промпт
плюс весь `facts_packet` в user-сообщении через `JSON.stringify(packet, null, 2)`.

Ответ судьи разбирает **настоящий код ноды** `agent-judge-parse` — из резервной копии
`tmp/backup/GLQ2iuzRaCQZM7QU/` с наложенным патчем `W1-writer-now` из `tests/b45/patches.json`
(тем же, что ушёл в n8n). Поэтому Proof Validator и сборка `writer_input` работают как в проде.
Тело запроса писателя собирает сам код ноды, стенд подменяет только модель и лимиты.

Меняется между прогонами только модель и параметры вызова. Вход, промпты и код разбора — одни и те же.

## Файлы

| Путь | Что там |
|---|---|
| `fetch.mjs` | выгрузка входов и эталонов Opus из Supabase |
| `run.mjs` | прогон модели: судья → разбор кодом ноды → писатель |
| `compare.mjs` | таблица «Opus против модели» и критерии приёмки |
| `mismatch-brief.mjs` | выжимка по сделкам с разошедшимся вердиктом |
| `schema.judge.json` | strict-схема ответа судьи для `response_format` |
| `prices.json` | цены Polza на flex, порог тревоги по запасному провайдеру |
| `labels.json` | решения Сани по спорным сделкам — настоящий эталон |
| `data/` | входы, эталоны, сырые ответы, журнал расходов — **вне git**, там цитаты клиентов |

## Запуск

```bash
node bench/fetch.mjs                          # обновить входы и эталоны из базы
node bench/run.mjs --model sol --limit 1      # одна сделка
node bench/run.mjs --model sol                # весь набор
node bench/run.mjs --model sol --judge-only   # без писателя
node bench/compare.mjs --model sol
node bench/mismatch-brief.mjs --model sol
```

## Деньги

Потолок стенда — 300 ₽, задан в `run.mjs` (`CEILING_RUB`). Журнал `data/ledger.json` копит все
вызовы; при достижении потолка прогон останавливается. Журнал сквозной: считает и прошлые запуски.

Кто ответил, по ответу не видно — поле `provider` у Polza всегда `openrouter`. Запасного
провайдера ловим по цене: `cost_rub` выше, чем «токены × цена flex», более чем в 1,6 раза.
Проверка встроена в каждый вызов, результат в журнале (`fallback_check`).

## Чего стенд не делает

Не собирает `facts_packet` с нуля — берёт готовый из базы. Значит проверяет судью и писателя,
но не сборщик фактов, не b4.5 и не транскрипцию.
