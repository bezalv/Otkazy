# Локальная проверка конкурентности PostgreSQL

`author-inference-real-pg.test.mjs` проверяет журнал попыток на нескольких независимых соединениях настоящего PostgreSQL. Скрипт `run-local-real-pg.sh` создаёт отдельный временный кластер с синтетическими таблицами: рабочая Supabase, переменные `DATABASE_URL` и настройки внешней базы не используются. TCP отключён, доступ идёт через Unix-сокет в приватном каталоге `/tmp/otkazy-local-pg-*`.

Нужны заранее имеющиеся Linux-бинарники PostgreSQL 16, соответствующие файлы инициализации и библиотеки, Node.js 24 и установленные зависимости `app`. Скрипт ничего не скачивает и не устанавливает. Все пути задаются явно:

```bash
export OTKAZY_LOCAL_PG_BIN=/абсолютный/путь/к/postgresql/16/bin
export OTKAZY_LOCAL_PG_CLIENT_BIN=/абсолютный/путь/к/клиенту/postgresql/16/bin
export OTKAZY_LOCAL_PG_SHARE=/абсолютный/путь/к/share/postgresql/16
export OTKAZY_LOCAL_PG_LIB=/абсолютный/путь/к/библиотекам
export OTKAZY_LOCAL_PG_NODE=/абсолютный/путь/к/node-24
bash tests/restore-worker/run-local-real-pg.sh
```

Для изолированного ручного сценария без таблицы очереди задайте перед запуском
`OTKAZY_LOCAL_PG_SUITE=manual-prejudge`. Он проверяет, что транскрипт и
подготовленные факты записаны до вызова подставного судьи.

Тест проверяет адрес сокета, имя и каталог базы, а также отключённый TCP до создания синтетических таблиц. При обычном завершении, ошибке, `INT` или `TERM` скрипт останавливает сервер и удаляет только собственный проверенный временный каталог. При `SIGKILL` очистка не гарантирована: перед ручной уборкой необходимо убедиться, что сервер остановлен и каталог принадлежит именно этому запуску.

Без явного тестового окружения `node --test tests/restore-worker/author-inference-real-pg.test.mjs` пропускает все сценарии. Проход локального теста не подтверждает схему или настройки рабочей базы и не делает запросы к Polza.
