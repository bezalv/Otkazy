# Ожидание поздних записей звонков

Внедрено 01.11.2026. Исторические сделки не перепрогонялись.

## Поведение

- Порог включения хранится в `lost_audio_wait_config.enabled_at`: 01.11.2026 13:53:54 Новосибирск. Проверяется дата последнего перехода в отказ, а не дата создания сделки.
- У будущего отказа проверяем завершённые `VOXIMPLANT_CALL` за сутки перед отказом и последующие звонки. Более старые отсутствующие архивы не заставляют ждать новую загрузку. `VOXIMPLANT_CALL` общий для интеграций, правило не привязано к Билайну.
- Запланированные дела, незавершённые звонки и нулевая длительность исключаются. Длительность здесь определяется по CRM-времени, поэтому короткое соединение/недозвон с положительной длительностью может попасть в ожидание: точной статистики телефонии у вебхука нет.
- Ссылка в `SETTINGS.RECORD_URL` или скачиваемый URL в `FILES` означает, что можно перейти к штатной проверке скачивания и транскрибации. Один ID файла недостаточен. Проверки содержимого файла и технических ошибок распознавания остаются штатными.
- При отсутствии файла до платных вызовов возвращается `waiting_audio`. Строка вердикта не создаётся, комментарий в CRM и уведомление РОПу не отправляются. Фиксированная пауза на пять минут удалена.
- Проверки относительно первого обнаружения: 5, 15, 30, 60 минут; далее ежечасно до 8 часов; контрольная через 24 часа. Планировщик опрашивает очередь каждые 5 минут, поэтому фактический момент может быть позже цели на один интервал, а при нагрузке/сбое — больше.
- На последней проверке сначала проверяется наличие файла. Если он появился — обычный разбор; если отсутствует — `недостаточно_данных` без вызова судьи, без обвинений менеджера. Это не «неправомерен». Очередь становится `expired`, автоматического пересчёта после этого нет.
- Успешный разбор и состояние `done` записываются одной транзакцией. Если сделка уже не в отказе, очередь отменяется. Технический сбой анализа не завершает очередь.
- Храним ID звонка, время окончания, первое обнаружение отсутствия и первое обнаружение аудио. Это интервальная оценка доступности, не точное время загрузки файла оператором. Телефоны, ссылки записи и токены в очереди не храним.

## Проверки и воспроизведение

Источник логики: `prototype/lib/audio-wait.js`. Сборщик патчей: `bench/build-audio-wait.mjs`.

Перед сборкой нужен полный экспорт пакета в `tmp/backup/2026-11-01-audio-wait/batch.json` (сам объект workflow с nodes/connections). Экспорт может содержать секреты, поэтому остаётся в игнорируемом `tmp/`.

```
node bench/build-audio-wait.mjs
node tests/audio-wait/run.js
```

Пройдено 29 проверок ожидания и интеграции с кодом нод, ещё 343 проверки существующих шлюзов/ночного повтора/пропусков/достаточности данных/уведомлений. SQL постановки, захвата и завершения проверен на синтетической сделке внутри `BEGIN ... ROLLBACK`, тестовых данных в базе не осталось. Оба графа прошли `validate_workflow`; сохранённые Code-ноды машинно совпали с подготовленными файлами. Остались четыре существовавших до правки предупреждения валидатора о префиксе `=` в SQL-полях.

Без приватного экспорта тесты выполняют 21 проверку чистой логики, интеграционную часть явно пропускают. Security advisor для новых таблиц выдаёт только информационное `RLS enabled, no policies`: отсутствие клиентских политик здесь намеренно, доступ клиентам закрыт.

Реальные сделки для теста не запускались. Полный цикл на живой записи ещё предстоит подтвердить на новом отказе с задержкой.

## Откат

Отключить только планировщик. В пакете восстановить три Code-ноды из экспорта до правки, соединить «По одной сделке» (выход 1) непосредственно с «Обработать 1 сделку», удалить `audio-wait-context`, опубликовать пакет. Очередь и конфигурацию можно оставить для диагностики. Исходный бэкап лежит в `tmp/backup/2026-11-01-audio-wait/batch.json`; версия пакета до изменения — `54eb8f7f-c5c1-4dd7-b8d0-1b47726ac564`.
