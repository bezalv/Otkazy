# Ночной и ручной повтор

Ночью после 04:00 по Новосибирску сохраняется неизменяемый план на день; при
перезапуске используются те же сделки и ключи заданий. В одной ночи выбирается
не больше 20 сделок. Во все сохранённые планы вместе, включая старые,
ставится не больше 20 новых ночных заданий за окно с 04:00 до 04:00 по
Новосибирску. Лимит проверяется по времени базы данных под общей блокировкой;
ручные и live-задания не входят в него. Не поместившиеся задания остаются
в неизменённом плане до следующего окна. Повтор уже созданного задания лимит
не расходует. План содержит отложенные случаи, для которых история
Битрикса не подтвердила актуальную дату отказа; такие сделки не получают
искусственный `pipeline_error`.

В отличие от старого отбора только по `last_attempt_at`, сначала рассматриваются
сделки, которые дольше всего не попадали в прошлые сохранённые планы. Это не даёт
постоянно откладываемой двадцатке навсегда заблокировать остальных. При равенстве
сохраняется порядок по `last_attempt_at`. Сделка с уже ожидающей, обрабатываемой
или требующей ручной сверки задачей не ставится в ночную очередь повторно.

Для каждого выбранного кандидата потребуются запрос текущей сделки и, если она
по-прежнему в отказе, запрос первой страницы истории стадий по убыванию даты. Увеличение общего
лимита или ускорение запросов требует проверки ограничений API Битрикса и нагрузки
других приложений. Автоматическая сверка периода простоя и пользовательский
интерфейс ручного прогона в этом модуле не включены.

Граница окна учитывается по времени базы при проверке лимита и постановке в
одной транзакции. Транзакция, начатая непосредственно перед 04:00, теоретически
может подтвердиться после 04:00: физическое время COMMIT не измеряется и строгое
ограничение количества подтверждений по нему не гарантируется. До пилота это
ограничение требует решения или явного принятия; счётчик также предполагает, что
строки ночной очереди не удаляются в течение текущего окна.
