# Ожидание записи звонка

Чистая логика `awAssess`, `awCandidate`, `awHasAudio` и константы перенесены из
`prototype/lib/audio-wait.js` ветки `fix/wait-for-call-recording`, коммит
`442852e31901330813cf0533335a08fa9cfd6de8`. Они не читают БД и не делают
сетевых вызовов. Проверки на реальных сделках не проводились.

`awAssess(calls, loseDate, enabledAt, saved, nowMs)` воспроизводит исходную
оценку и возвращает состояние `disabled`, `ready`, `waiting`, `expired` или
`terminal`. `saved` — ранее сохранённая строка `lost_audio_wait`. Для повторной
проверки передаются исходный `first_seen_at`, `deadline_at` и `observations`,
поэтому повтор не сдвигает срок. `enabledAt` нужно брать из текущей
`lost_audio_wait_config`, сохраняя исходную дату включения правила.

`planAudioWait({ stageId, callsComplete, calls, loseDate, enabledAt, saved,
nowMs, silent, screenshots })` превращает оценку в одно из решений:

- `skip` при смене стадии с `cancelWaitingQueue: true` только для ожидающей
  записи либо при уже завершённом ожидании с причиной `audio_wait_terminal`.
- `source_incomplete` при сбое чтения звонков. Запись очереди не меняется,
  обработку ошибки продолжает основной шлюз полноты данных.
- `waiting` с рассчитанной очередью и флагами запуска. Анализ и вердикт ещё
  не создаются.
- `expired` с рассчитанной очередью и исходным шаблоном результата
  «недостаточно_данных». Вызывать судью для этого результата не нужно.
- `analyze`, если правило выключено либо необходимые записи появились.
  При наличии `queue` после успешного анализа её нужно завершить.

Планировщик обязан передать для повтора сохранённые флаги `silent` и
`screenshots`. `queueStateAfterAnalysis(plan, status)` подсказывает `done`
только для успешного `processed` с существующей очередью; при ошибке возвращает
`null`. Это рекомендация вызывающему коду, сама функция ничего не записывает.

Интеграция ещё требуется: транзакционная запись результата вместе с `done`
или `expired`, безопасный захват задач с арендой и восстановлением после
сбоев, отмена ожидания при смене стадии, проверка задержанного аудио до платных
вызовов и передача ошибок в шлюз полноты. Приватный экспорт пакета
`tmp/backup/2026-11-01-audio-wait/batch.json`, на котором собирались
интеграционные тесты исходной ветки, отсутствует в этой локальной копии.
Поэтому соответствие интеграции и работу на живых данных ещё нужно проверить.

Запуск моков из корня проекта: `node --test tests/restore-audio-wait/run.mjs`.
